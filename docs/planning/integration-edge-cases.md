# Integration Edge Cases & Decisions (P2)

> **What this is:** issues that only appear at the *boundaries between
> components* — invisible inside any single service, guaranteed to bite at
> integration time. Each row records the decision taken. New rows are appended
> as work surfaces them.
> Source of truth: [phases.md](phases.md) §4.

| # | Edge case | Between | Why it bites | Decision / mitigation | Status |
|---|---|---|---|---|---|
| 1 | **CORS** — the console (Next.js) calling backend APIs (localhost:8xxx) gets blocked | console ↔ backend services | Each piece works "fine" in isolation; the first integration demo fails with CORS errors and nothing owns it | Policy set: all services allow `http://localhost:3000` and `http://localhost:3030` in `dev` only (contracts README §5). Applied via the service template. Production: same-origin via gateway (P6) | Decided, applied in template |
| 2 | **Envelope `extra="forbid"` + version skew** — a consumer validates fields it doesn't know and rejects a newer producer's event | shared lib ↔ all services | Envelope is the shared contract; a v0.3 field added for one service breaks every other consumer until the whole monorepo is on the same lib | Monorepo editable install = one lib version everywhere (no skew by construction). Rule: **additive-only** changes, defaults for new fields; catalogue updated in the same commit (telemetry-model §3.5 rules) | Standing rule |
| 3 | **At-least-once duplicates** — the same event redelivered after a crash, double-recorded in Postgres / double-processed | eventbus ↔ services | Eventbus semantics are at-least-once by design (ADR-0004); naive consumers record duplicates and DI metrics (CFR) silently inflate | Consumers idempotent on `envelope.id`; deployments-service has a **unique index on event_id** (contract: 200 on replay). Documented in catalogue rule 4 | Implemented in deployments-service |
| 4 | **Readiness honesty** — a service with no DB reports `/ready` = ok forever | probes ↔ services | Registry aggregates `/ready`; the demo looks healthy during a Postgres outage → false confidence, and P6 SLO burn-rate alerts become meaningless | Template contract: `/ready` must check real dependencies (Postgres/Redis ping). Catalog stays always-ready (in-memory, documented). Registry derives status from `/ready` only | Standing rule |
| 5 | **Metric label drift** — one service adds/removes a label on a shared metric name | services ↔ dashboards | Prometheus silently drops series when label sets change → dashboards go blank with no error; P3 anomaly pipeline trains on polluted history | Shared names keep the **exact label set** from the template (`service/method/path/status`). New metric names are reviewed; catalogue/dashboard rows updated in the same commit | Standing rule |
| 6 | **`trace_id` never reaches log lines** — Tempo→Loki jump silently no-ops | logging ↔ RCA (P4) | Grafana datasources already map `trace_id` for the jump; if python logging doesn't attach it from the OTel context, RCA evidence links break later | P2 logs work includes OTel logging instrumentation (envelope has a `trace_id` field — populate it). Verified at the integration checkpoint | Implemented (services log with envelope) |
| 7 | **CI can't reach local Redis/Postgres** — "every deploy emits deploy events" is impossible from GitHub Actions | CI hook ↔ DI-1 | The P2 gate requires deploy events recorded; a CI-only hook would point at nothing | Two paths: (a) compose-side script posts to :8701 on `infra-up`/redeploy — **this is the gate path**; (b) CI hook is best-effort, emits only metadata, clearly documented as gap. DI-1 API is the contract for both | Decided |
| 8 | **Contract drift** — a FastAPI spec diverges from `docs/contracts/` and the mock server goes stale | services ↔ contracts ↔ console | The console works against the mock; a diverged real API breaks the page with no error at the contract level | ✅ **IMPLEMENTED** — `scripts/check_contract_drift.py` + `docs/contracts/manifest.json` in CI (`python-quality` job); contract must be a subset of the live API. First catch on day one: catalog 404 wasn't declared in the route decorator (fixed) | Implemented in CI |
| 9 | **Deploy-event timestamps** — consumers stamping with their own clock | producers ↔ consumers ↔ DI-4 (P3) | `bad_after_s` and MTTD math skew if consumers use `stored_at`; container clocks differ | `envelope.timestamp` (UTC, producer) is authoritative for all timing; `stored_at` is audit-only (contracts README §3, catalogue rule 3) | Standing rule |
| 10 | **New service lands in only one runtime** — added to compose but not K8s base / CI job | services ↔ infra | ADR-0005 requires 1:1 parity; drift shows up in P7 (kind) as missing manifests and a "works on my machine" story | PR template checklist: compose + K8s base + CI `python-quality` + port register in the same change | Standing rule |
| 11 | **Orphan event types** — an event published that no consumer reads (or a consumer waiting on a stream nobody writes) | any ↔ any | Streams are created on demand; a "dead" event type costs debugging time and pollutes the catalogue | Envelope validates types at construction (typos fail fast). New types require catalogue update in the same commit | Standing rule |
| 12 | **Stream growth in long dev sessions** — no retention configured → Redis memory balloons | eventbus ↔ all | `stream_ttls` defaults to none; a week of dev traffic on `st:log`/`st:metric` grows unbounded | Retention map set at service startup (catalogue §3.5): metrics/health 1 h, logs 24 h; deployment long (Postgres is the store) | Implemented |
| 13 | **Mock→real API swap** — console features flip from mock to live as APIs land | console ↔ backend | If the swap isn't per-feature and tested, mixed mock/live state is indistinguishable from a real bug during demos | Per-feature swap only; console marks mock-sourced pages with a "MOCK" badge in dev until the real API is verified against the contract | Implemented in console |
| 14 | **`.env` committed by accident** — dev creds enter history | any | `aegisshop/.env`, `*.env.local` are gitignored — but a force-add or a new env file name bypasses it | Restated in PR template; if it ever happens: rotate dev creds (they're dev-only by policy — `.env.example` ships no real secrets) | Standing rule |
| 15 | **Cross-service state coupling in AegisShop v1** — nothing sets order status `paid` when payment succeeds; order items need the cart's contents | order ↔ payment ↔ cart | If payment just inserts a row, orders stay `created` forever; if services call each other ad hoc, contracts mutate silently and the mock server goes stale | **D8/D9 decisions:** order reads cart via `GET /cart/{user_id}`; payment→order via explicit `POST /orders/{order_id}/paid`. Rule: any cross-service call must appear in `docs/contracts/` first (contract-first) | Decided, contract-first rule stands |

**How this register is maintained:**
1. Anything changing a contract, envelope, or runtime parity needs a
   decision row here (or in the planning decision log) — never silent.
2. The register is a working doc: rows close when the mitigation lands
   (verified in code/CI), not when they're "agreed".
